# Reactive Perception และ Spatial Memory แบบประวัติ 5 ครั้ง

อัปเดต 3 พฤศจิกายน 2026 — โปรเจกต์ `AIAdventureRPG` / `AdventureTinyLLM` (เผยแพร่เป็นตัวอย่างใน AdventureTinyLLM v0.3.0)

## 1. วัตถุประสงค์

AI ต้องตอบสนองได้เมื่อพบ **มอนสเตอร์ สมุนไพร หนาม ผลไม้ LoreStone หรือ NPC ใหม่** โดยไม่จำเป็นต้องรอให้คำสั่งเดินระยะไกลจบ และต้องไม่เรียกโมเดลซ้ำ ๆ เมื่อวัตถุเดิมแกว่งอยู่ตรงขอบรัศมีตรวจจับ

แยกระบบเป็น:
- **Vision**: มุมมองด้านหน้า 170°, ระยะ 30 หน่วย, ตรวจสิ่งกีดขวาง; สแกนประมาณทุก 0.28 วินาทีเกม
- **CombatState**: มอนสเตอร์รอบตัว 360° ภายใน 9 หน่วย และตรวจการเตรียมโจมตีประมาณทุก 0.12 วินาทีเกม
- **PerceptionMemory**: เขตแจ้งเหตุ **9 หน่วย**, เขตยืนยันว่าออกไปไกลพอก่อนแจ้งอีกครั้ง **18 หน่วย**, พร้อมแผนที่ความจำและ FIFO 5 ภาพบันทึกต่อพิกัด
- **Tiny/Ollama**: ได้รับสัญญาณให้คิดใหม่เมื่อมีวัตถุใหม่เข้าระยะ พร้อมข้อมูลความจำที่ค้นในจังหวะตัดสินใจ

## 2. กฎ 9/18 หน่วย — ป้องกันการแจ้งซ้ำ

แยกวัตถุด้วย Unity Entity ID ใน **รอบการเล่นปัจจุบัน** ไม่ใช่แค่ชื่อหรือพิกัด เพราะมีต้นสมุนไพรหลายต้นที่ชื่อเหมือนกัน

1. ถ้าเริ่มเห็นวัตถุที่ยังไม่แจ้ง แล้วเข้ารัศมี `distance <= 9` หน่วย: **แจ้งเพียงครั้งเดียว** และปิดสวิตช์แจ้งซ้ำของ ID นี้
2. ถ้าวัตถุเดิมไปอยู่ระหว่าง 9 และ 18 หน่วยแล้วกลับมา <= 9: **ไม่แจ้งอีก**
3. ถ้าระยะที่สังเกตได้มากกว่า 18 หน่วยจริง หรือผู้เล่นอยู่ไกลกว่า 18 หน่วยจากตำแหน่งที่เห็นครั้งล่าสุด: เปิดสวิตช์อีกครั้ง
4. เมื่อวัตถุเดิมกลับเข้ามา <= 9 หลังจากข้อ 3: แจ้งใหม่ได้ 1 ครั้ง
5. ไม่ถือว่าการมองไม่เห็นเพราะหันหลัง/สิ่งกีดขวางเป็นการออกนอกวง 18 หน่วยโดยอัตโนมัติ
6. ถ้ามีหลายวัตถุถูกพบในช่วงสแกนเดียวกัน **รวมการขอคิดใหม่เป็นครั้งเดียว** โดยมีคูลดาวน์ 0.65 วินาทีเกม แต่แผนที่จะบันทึกวัตถุทั้งหมด

มอนสเตอร์ในระยะ 9 หน่วยถูกตรวจได้แม้อยู่ด้านหลัง (ตาม CombatState 360°); วัตถุอื่นต้องผ่าน Vision จึงจะถือว่าเห็นจริง

การรับรู้ใหม่ **ไม่ให้ Reward** การเห็นหนามไม่เท่ากับการหลบสำเร็จ และไม่สร้างคะแนนบวกหรือโทษเอง

## 2.1 สัญญาณอันตรายเร่งด่วน (AttackWindup)

ปรับเพิ่มเติม 3 พฤศจิกายน 2026: **การง้างโจมตีของมอนสเตอร์ตัวเดิมก็เป็นเหตุการณ์ Reactive ใหม่ได้** ไม่ต้องออกจากวง 18 หน่วยก่อน ต่างจากกฎค้นพบวัตถุใหม่

- `AdventureCombatState` สแกนมอนสเตอร์ภายในรัศมีตรวจจับ หากมอนสเตอร์ยังมีชีวิตและเริ่ม `IsWindingUp` จะส่ง `AttackWindup` ให้ `AdventurePerceptionMemory` ทันที
- ใช้ ID มอนสเตอร์และเวลา `WindupEndsAt` เป็นตัวแยกการง้าง **หนึ่งครั้งแจ้งหนึ่งครั้ง**; การสแกนซ้ำระหว่างง้างครั้งเดิมไม่เรียก AI ซ้ำ
- แจ้งโดยตรง **ไม่รอคูลดาวน์ 0.65 วินาที** ของการค้นพบวัตถุธรรมดา; ไม่เผยการง้างของมอนสเตอร์นอกระยะ 9 หน่วย
- หาก AI กำลังเดิน จะหยุดก่อน แล้ว Tiny/Ollama จะยกเลิกคำตอบเก่าและประเมินสถานะใหม่ เพื่อให้โมเดลเลือกหลบ ต่อสู้ หรือรักษาตัวตามที่เรียนรู้ ไม่บังคับหลบด้วยสคริปต์
- **ไม่ให้ Reward จากการได้ยินสัญญาณ/เห็นการง้าง** ยังคงให้รางวัลหลบสำเร็จเฉพาะเมื่อหนีออกนอกระยะก่อนการโจมตีและเป็นการเคลื่อนที่จริง
- Tiny ป้องกันการส่งคำขอ `/act` ที่ล้าสมัย หากการเข้ารหัส observation เองเกิดสัญญาณเร่งด่วน

**ข้อจำกัดที่สำคัญ:** หน้าต่างง้างโจมตีเริ่มต้น 0.55 วินาทีเกม; การร้องขอโมเดลผ่าน HTTP อาจไม่ทันโดยเฉพาะโหมดเร่งความเร็วเกมหลายเท่า จึงถือว่าระบบนี้เป็นการเรียกคิดใหม่อย่างเร่งด่วน **ไม่ใช่การรับประกันว่าจะหลบการโจมตีได้**

## 3. ระบบแผนที่พิกัดแบบ FIFO 5 ชุด

`AdventurePerceptionMemory` ใช้ช่องพิกัด X/Z ขนาด **2 หน่วย** (`coordinateCellSize`). เมื่อเจอสิ่งของ ณ ช่องหนึ่ง จะค้น `HistoryAt(position)` แล้วอ่าน **5 รายการล่าสุด** (เก่าสุดออกก่อนเสมอ)

แต่ละ Snapshot บันทึก:
- ชนิดวัตถุและชื่อ (`kind`, `name`)
- พิกัด X/Y/Z ที่พบจริง (`position`)
- เวลา UTC (`utc`) และ ID ที่พบในรอบการเล่น (`source`)
- สถานะ `FirstSeen`, `Unchanged`, `Moved`, `MovedAway`, `Changed`

**ไม่บันทึกซ้ำทุกการสแกน**: สมุนไพรที่ไม่เคลื่อนที่บันทึกครั้งแรก และเว้นอย่างน้อย 8 วินาทีเกมจึงยืนยันตำแหน่งว่า `Unchanged` อีกหนึ่งครั้ง ส่วนมอนสเตอร์ที่เปลี่ยนพิกัดเกินเกณฑ์/ย้ายช่องจะบันทึก `MovedAway` ที่พิกัดเก่ากับ `Moved` ที่พิกัดใหม่ เพื่อให้ตรวจสอบอดีตได้

ตัวอย่างประวัติ 5 รายการ ณ พิกัด (14, 22):
```text
1. Herb / Forest herb  FirstSeen
2. Herb / Forest herb  Unchanged
3. Herb / Forest herb  Unchanged
4. Monster / Wild Boar  Moved
5. Monster / Wild Boar  MovedAway
```
เมื่อพบสิ่งใหม่ที่พิกัดนั้น ระบบจะสามารถบอกได้ว่าสมุนไพรยังคงอยู่เดิม แต่มอนสเตอร์เคยผ่านจุดนี้และย้ายไป (ตัวอย่างสมมติ ไม่ใช่ข้อมูลที่วัดจากเกม)

**เก็บข้ามการเล่น**: เซฟ JSON ลง `Application.persistentDataPath/AIAdventureRPG/perception-map-v1-<mapSeed>.json` เก็บแยกตาม `mapSeed` และตรวจขนาดโลกก่อนโหลด ใช้การเขียนไฟล์ชั่วคราวแล้วแทนไฟล์เดิม ไม่แตะไฟล์ save เกมอื่น กำหนดจำนวนช่องสูงสุดได้ (ค่าเริ่มต้น 2,048 ช่อง) และบันทึกอัตโนมัติทุก 10 วินาทีเกมเมื่อข้อมูลเปลี่ยน

## 4. นำประวัติไปใช้ในจังหวะตัดสินใจจริง

**Ollama:** ทุกครั้งที่สร้าง Prompt `AdventureOllama` จะอ่าน `DecisionMapReport` จากวัตถุที่เห็นหรือมอนสเตอร์ที่ตรวจจับรอบตัวได้ (สูงสุด 4 พิกัด) และแนบประวัติ 5 รายการที่พิกัดนั้น โดยจัดลำดับ **มอนสเตอร์ที่กำลังง้างโจมตี → วัตถุใหม่ที่เพิ่งพบ → มอนสเตอร์ในรัศมี Combat → วัตถุที่เห็นทั่วไป** หากมีหลายพิกัดจะใส่เป็นบริบทรอง โดยไม่เปิดเผยตำแหน่งปัจจุบันของมอนสเตอร์นอกวงตรวจจับ

**Tiny:** ขยาย observation จาก 51 เป็น **56 ค่า** โดยเก็บ 51 ค่าเดิมและเพิ่ม:
- **51**: มีเหตุการณ์รับรู้ใหม่ใน 5 วินาทีเกมล่าสุดหรือไม่ (0/1)
- **52**: จำนวนประวัติ ณ พิกัดวัตถุที่กำลังสนใจ / 5
- **53**: จำนวนการเปลี่ยนแปลงที่พิกัดนั้น / 5
- **54**: ความสม่ำเสมอของพิกัดนั้น (0–1; สูงคือไม่มีความเปลี่ยนแปลง)
- **55**: วัตถุที่กำลังสนใจเคยเคลื่อนที่ระหว่างสแกนในรอบการเล่นปัจจุบันหรือไม่ (0/1)

Tiny ไม่ได้รับข้อความ Snapshot ทั้ง 5 เหมือน Ollama เพราะใช้โมเดลตัวเลขขนาดเล็ก จึงได้รับ **สรุปเชิงตัวเลขของประวัติ** ที่ค้นสดใน `Encode()` ตอนออกคำสั่งใหม่ และเลือกพิกัดด้วยกฎความสำคัญเดียวกัน แม้มอนสเตอร์จะอยู่ด้านหลังตัวละคร หากง้างโจมตีจะใช้ประวัติพิกัดมอนสเตอร์แทนวัตถุด้านหน้า

การปรับขนาดจาก 51→56 ทำให้น้ำหนัก 51 เดิมใช้ตรง ๆ ไม่ได้ จึงเก็บสำรองไว้ที่:
`T:\Space\Projects\ProjectsAI\AdventureTinyLLM\checkpoints\legacy\tiny-unity-pre-spatial-v4-51features-2026-11-03.pt`
(ตรวจพบว่ามี 17,469 training steps ก่อนสำรอง) และเริ่มโมเดล 56 ค่าใหม่ที่ schema v5, โปรโตคอล `explicit-action-id-v6-spatial`

## 5. Reactive replan และการให้คะแนน

เมื่อ PerceptionMemory ส่ง `ImportantChange`:
1. ฝั่ง Agent หยุด finite move ที่ค้าง (`new perception`) ถ้ากำลังควบคุมโดย AI
2. Tiny: ล้างการผูก Reward กับ action ID เดิม, ยกเลิก HTTP `/act` ที่ค้าง, ปฏิเสธคำตอบเก่าด้วย generation token แล้วขอคำตัดสินใจใหม่โดยเร็ว
3. Ollama: ยกเลิกคำตอบที่ค้าง, ล้างคำสั่งชั่วคราว, บันทึกข้อมูลวัตถุใหม่และประวัติพิกัดลง Context แล้วขอใหม่
4. ไม่อัปเดตน้ำหนักจากการแค่เห็นสิ่งใหม่; เฉพาะการกระทำที่มีผลจริงจึงได้รับ Reward ตาม `AdventureRewardPolicy`

เพิ่มแรงจูงใจ:
- โจมตีปกติโดน **+0.35** (จาก +0.25)
- สกิลโจมตีโดน **+0.40 ต่อเป้าหมาย**, จำกัดโบนัสจากการโดนไว้สูงสุด +0.65 (เดิม +0.30 และ +0.50)
- ฆ่ามอนสเตอร์ **+1.45** เหมือนเดิม และผลลัพธ์ทั้งหมดมี clamp ตามกฎเดิม

## 6. การทดสอบและข้อจำกัด

- Unity EditMode: **81/81** ผ่าน (เพิ่มทดสอบ AttackWindup ไม่ซ้ำและการยกเลิกเครดิตที่ล้าสมัย) รวมการตรวจคะแนนโจมตีใหม่, ลำดับเลือกพิกัดที่มีมอนสเตอร์ด้านหลัง, Tiny Encode และไม่เปิดเผยตำแหน่งมอนสเตอร์นอกวง
- Tiny Python: **29/29** ผ่านสำหรับ schema 56
- PlayMode: สร้างมอนสเตอร์ทดสอบด้านหลังตัวละครในระยะ 8 หน่วย แล้วตรวจว่า Tiny replan จริง, HP/MP ไม่เปลี่ยนจากการเห็น, อยู่ 9/18 หน่วยไม่มีแจ้งซ้ำ, ออก >18 แล้วกลับเข้า <=9 จึงแจ้งใหม่
- ทดลอง Tiny Train ด้วย schema 56 รับคำสั่งได้จริงโดยไม่มี API failure ในช่วงทดสอบ
- ตรวจไฟล์แผนที่จริงพบประวัติสูงสุด 5 รายการต่อช่องตาม FIFO (จำนวนช่องเปลี่ยนตามการเดินสำรวจ)
- ใน Play Mode เรียก Ollama สร้าง Prompt จริงแล้ว ตรวจพบ `Spatial map history for currently visible or sensed coordinates` พร้อมข้อมูลย้อนหลังของหนามที่เคยเห็น

**ข้อจำกัด:** สแกนปัจจุบันยังไม่รวมต้นไม้ตกแต่งทุกต้น (ต้นไม้บางชนิดไม่ได้เป็นวัตถุที่ Vision ตรวจจับได้); แผนที่เป็นความจำจากสิ่งที่ **เคยตรวจพบ**, ไม่ใช่ระบบรู้ทุกตำแหน่งของวัตถุในโลก นอกจากนี้ AI ยังใช้รูปแบบการฝึก one-step actor-critic ไม่ใช่ระบบวางแผนระยะยาวแบบเต็มตัว
