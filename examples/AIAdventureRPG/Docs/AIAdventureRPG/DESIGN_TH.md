# AI Adventure RPG — เอกสารออกแบบและสถานะการพัฒนา

## เป้าหมาย
เกมผจญภัย 3D ให้มนุษย์เล่นได้ และ AI ใช้ควบคุมตัวละครเดียวกันด้วยกติกาเดียวกัน มุ่งเรียนรู้ผลการกระทำผ่านโลกจำลอง

## การเลือกโหมด AI และ HUD ที่สัมพันธ์กับความละเอียด (2026-11-02)

แถบควบคุมด้านบนแยก MANUAL / TRAIN TINY / USE TRAINED / OLLAMA เป็นคนละปุ่ม ไม่ใช้ Train/Evaluate ที่ซ่อนในแผงสถานะอีกต่อไป UI ตรวจสอบ Tiny REST `/health` เป็นระยะ: ต้องมี API และอนุญาตให้ฝึกจึงเลือก TRAIN TINY ได้; USE TRAINED ต้องยืนยันว่ามีน้ำหนักฝึกแล้วและมี training_steps มากกว่า 0 มิฉะนั้นปุ่มใช้โมเดลฝึกแล้วถูกปิดไว้ เมื่อออกจาก Tiny จะล้างคำสั่งค้างและคืนเวลา 1x เริ่ม Play Mode ที่ Manual โดยไม่ฝึกเองอัตโนมัติ

HUD ใช้สัดส่วนเดียวกันทั้งหน้าต่าง กล่องข้อมูล ตัวหนังสือ และพื้นที่คลิกจาก reference size 1600×900 โดยใช้ scale = min(screenWidth/1600, screenHeight/900) และให้ Stats, Log และ AI Status เลื่อนได้ ไม่ใช้ขนาดพิกเซลคงที่ที่แตกสัดส่วนตอนเปลี่ยน Game View

## ทิศทางการหันหน้าตัวละครขณะเดิน (2026-11-02)

ในโหมด Tiny/Ollama/Local ระหว่างคำสั่งเดินแบบกำหนดระยะ ตัวละครจะหมุนแบบราบตาม X/Z ของตำแหน่งที่ตัวควบคุม Rigidbody ทำการเคลื่อนที่ในแต่ละ FixedUpdate โดยใช้ `AdventureFacing.ForTravel` และ `Rigidbody.MoveRotation` ถ้า Navigation เบี่ยงทิศ ตัวละครต้องหันไปตามทางที่ถูกเบี่ยงจริง แทน `face_x/face_z` เดิมซึ่งอาจไม่ตรงกัน; ขณะยืนเฉย ๆ หรือถูกบล็อกจะไม่หมุนโดยอัตโนมัติ และยังสั่งให้หันเพื่อสนทนาหรือโจมตีได้ในคำสั่งที่ไม่มีการเดิน ระหว่างเดินขึ้น/ลงที่ลาดชันใช้เพียง XZ เพื่อไม่ให้ตัวละครก้มหรือเงย การควบคุมคนผ่าน WASD และความเร็ว/กล้องไม่เปลี่ยน

## คำสั่ง AI เดินแบบกำหนดระยะ + ข้อมูลเหตุการณ์ (2026-11-02)

ผู้เล่นใช้ WASD ต่อเนื่องเดิมทุกอย่าง เฉพาะ Ollama/Tiny กำหนดทิศทาง XZ และระยะเดิน (world units) โดย Unity motor จะนับระยะที่เคลื่อนที่ได้จริง ไม่ใช่นับเวลา การเดินครบตามงบระยะ หยุดเมื่อชน/ถูกขวาง หรือได้รับบาดเจ็บ จะให้ AI ตัดสินใจใหม่ `AdventureEventJournal` บันทึกพิกัดสิ่งที่มองเห็น จุดที่เดินไปถึง สิ่งกีดขวาง และผลของปฏิสัมพันธ์จริงเป็นประวัติ มีทั้งข้อความให้ Ollama อ่าน และข้อมูลเชิงตัวเลข 8 ค่าใหม่ให้ Tiny (40 ค่าเดิมรวม) Tiny มีหัวเลือกระยะ 5 ตัวเลือก (1,2,4,6,10) และฝึก direction+distance จาก reward ของการเดินเดียวกัน น้ำหนัก Tiny รุ่นเก่า 490 steps เก็บสำรองต่างหาก และเริ่มฝึกใหม่เนื่องจาก schema เปลี่ยน (v2)

## แผนที่
สร้างใหม่เป็น AdventureValley จาก WorldModule, VoxelWorld, TerrainGenerator, VoxelMesher และ VoxelTerrainView ของระบบเดิมจริง ขนาด 64×32×64 voxel / 1 หน่วยต่อ voxel แม่น้ำ ภูมิประเทศต่างระดับ และธรรมชาติ

## กล้องและเซนเซอร์
- ใช้กล้องเดิมแบบบุคคลที่สามตามหลังตัวละครตลอดเวลา ทั้งผู้เล่นและ AI ไม่สลับเป็นบุคคลที่หนึ่ง
- เมาส์ขวาหมุนกล้อง ล้อเมาส์ซูม ผู้เล่นใช้ WASD ตามทิศกล้อง และ Shift เพื่อวิ่ง
- AI มีเซนเซอร์แยกจากกล้องแสดงผล ใช้ทิศที่ตัวละครหันหน้าเป็นหลัก ตรวจเห็นไกล 30 หน่วย / 170 องศา และใช้ Raycast ตรวจสิ่งกีดขวาง รับรู้ประเภทวัตถุ ชื่อ ระยะ ทิศทาง และพิกัดของสิ่งที่มองเห็น (ไม่ใช่ภาพพิกเซลจากกล้อง)
- AI รับพิกัดของตัวเอง (X/Y/Z), ขอบเขตแผนที่และทิศการหัน (+X ตะวันออก, +Z เหนือ) เพื่อเดินสำรวจหรือกลับไปยังจุดที่จำได้
- เมื่อปฏิสัมพันธ์สำเร็จ เกมรายงานชื่อสิ่งที่เจอ การกระทำ พิกัด และค่าความเปลี่ยนแปลงจริงของ HP / Knowledge / Happiness / Boredom ก่อน–หลังเหตุการณ์ให้ AI เรียนรู้จากผล ไม่ส่งตารางกฎลับให้ดู
- HUD ด้านบนมี 4 โหมดชัดเจน: MANUAL (คนเล่น), TRAIN TINY (ฝึกด้วยผลเกมจริง), USE TRAINED (ใช้โมเดล Tiny ที่มีน้ำหนักฝึกแล้ว ไม่อัปเดตจาก Unity), OLLAMA (ใช้โมเดล Ollama แยกต่างหาก); TAB สลับแบบปลอดภัย Manual → Ollama → Tiny ที่ฝึกแล้วถ้ามี → Manual โดยไม่เริ่ม Train ทางลัด

## ค่าสถานะ
- Health: หนาม −18, สมุนไพร +26, หมดเลือดกลับแคมป์
- Knowledge: ตอบ NPC ถูก +12, ผิด −7
- Happiness (แทน Relationship เดิม): เริ่ม 55, สมุนไพร +6, Amberberry +8, LoreStone +4, คุย NPC +9, ชนะมอนสเตอร์ +15; การกินพิษ/บาดเจ็บทำให้ลดลง
- Boredom: เพิ่มจากเวลาสะสมในโซนเดิมหลังครบ 35 วินาทีเกมเท่านั้น ไม่ขึ้นกับการยืนนิ่งหรือความเร็วการเดิน เมื่อเต็ม 100 จะลด Health, Knowledge และ Development ส่วน Happiness ลดแยกต่างหากเมื่อไม่มีความคืบหน้า ไม่คิดซ้ำ
- Full Boredom (ปรับใน AdventureStats Inspector): Health −3/นาที, Knowledge −2/นาที และ Development −1/30 วินาทีเกม; Happiness −3/นาทีหลังไม่มีความคืบหน้า 12 วินาที แม้เดินขยับอยู่; ค่าสถานะไม่ติดลบ
- Development: รับแต้มสะสมจากเหตุการณ์ระหว่าง 5 นาที; หากไม่ก้าวหน้าอาจลดลง
- Journal: เก็บประวัติเหตุการณ์จริง CSV

## ระยะสำรวจเมื่อสุ่มเดิน (2026-11-02)

Tiny Controller คงทิศการเดินที่สุ่มจากนโยบายไว้ 1.8 วินาทีเกม **หลังได้รับคำตอบจาก API** (เดิม 0.7 วินาที และเดิมเริ่มจับเวลาไปพร้อมการขอคำตอบ) เพื่อให้การทดลองทิศใหม่เคลื่อนที่ได้ไกลขึ้น ตัวกรองทิศที่ติดขอบแผนที่ยังทำงาน และโมเดลไม่ถูกป้อนตำแหน่งเป้าหมายล่วงหน้า

## การเสียชีวิตให้โทษรุนแรง (2026-11-02)

ความเสียหายที่ทำให้ HP เหลือศูนย์และการเสียชีวิตจากความเบื่อสะสมจะสร้างเหตุการณ์ `death=true` ที่ทำให้ Tiny Reward = **−2.0** เมื่อสามารถผูกกับ action_id ที่ใช้จริงได้ การเสีย 10 HP ตามปกติมี Reward ประมาณ −0.4 เหตุการณ์ fatal ที่แจ้งไปแล้วจะไม่ส่งซ้ำเมื่อกลับเกิดใหม่ในแคมป์ และแสดงจำนวนครั้งที่ตายใน HUD

## AI เดินติดมุม: Legal Action Masking (2026-11-02)

พบสาเหตุจาก Unity Play Mode จริงหลังฝึกมากกว่า 15,000 Steps: ตัวละครที่ X=62 Z=2 สั่งเดิน (+X,−Z) ซ้ำ ทำให้การ Clamp ขอบแผนที่หยุดการเคลื่อนที่ทั้งหมด แต่ยังคงยิง API และเกิด No-progress Penalty ระบบเดิมไม่มีการห้ามเลือกทิศทางที่เป็นไปไม่ได้ใน Action Head

แก้โดยเพิ่ม `AdventureActionAvailability` คำนวณชุด 9 ทิศตามขอบแผนที่ 2..(Width−2), 2..(Depth−2) ส่งเป็น `valid_moves` ใน `POST /act` API ใช้ mask logits ก่อนเลือกคำสั่งทั้ง Train และ Evaluate และเก็บ mask เดียวกันเพื่อทำ Move Policy Gradient หลังผลของการกระทำเกิดจริง จึงไม่ให้รางวัลกับระบบช่วยเปลี่ยนทิศหลังโมเดลตัดสินใจ สำหรับการอยู่นิ่งติดขอบเป็นเวลานานจะปิดตัวเลือก Idle เมื่อมีทิศทางเข้าด้านในได้แล้ว และหากไม่คืบหน้าเกิน 12 วินาทีเกมขณะอยู่ห่างจากขอบไม่เกิน 8 หน่วย จะเปิด Persistent Escape Mask ให้เลือกทิศที่เข้าด้านในต่อเนื่องจนห่างจากขอบที่เริ่มติดอย่างน้อย 16 หน่วย คำสั่งเคลื่อนที่ที่ถูกบังคับด้วย Escape Mask ไม่รับ Move Reward เพื่อไม่อ้างว่าเป็นทักษะที่โมเดลเรียนรู้เอง และหากการตอบ API ช้าจนตำแหน่งเปลี่ยน จะทิ้งคำสั่งที่ผิดขอบใหม่แทนการนำไปใช้งาน

ทดสอบกับ Checkpoint เดิมในมุมขวาล่าง (62,2) เรียก API ได้ทิศทางตะวันตกเฉียงเหนือ และ Unity Evaluate เดินออกจากมุมได้ ~2.7 หน่วยโดยไม่มี API Error; ชุดทดสอบ Unity เช็กขอบ, การเดินขนานขอบ, และพื้นที่เปิด ทั้งนี้เป็นการป้องกันติดขอบโลกเท่านั้น ยังไม่ใช่ NavMesh/Pathfinding หลบต้นไม้ หิน หน้าผาอย่างสมบูรณ์

## ระบบโซนความคุ้นเคย (Zone Fatigue) — โซนขนาดใหญ่

ขนาดแผนที่แนวนอน 64×64 หน่วย แบ่ง **โซนความเบื่อ 4×4 โซน แต่ละโซน 16×16 หน่วย** (จุดวาง NPC/ไอเทมแบบสุ่ม 8×8 เป็นคนละระบบ) แก้ขนาดโซนได้ที่ `AdventureStats.zoneCellSize` ใน Inspector

- เริ่มนับความคุ้นเคยเป็นวินาทีเกมทันทีที่เข้าโซน หลังสะสมครบ **35 วินาทีเกม** จะเริ่มเพิ่ม Boredom +0.25/วินาที แม้ AI เดินไปมาภายในโซนนั้น
- การเดินหรือยืนนิ่งไม่เพิ่มหรือลด Boredom โดยตรง การเดินข้ามขอบโซนต้องอยู่พื้นที่ใหม่ **1.5 วินาที** จึงจะเปลี่ยนโซนจริง การเก็บสิ่งของและสนทนาสำเร็จยังลด Boredom ตามผลกิจกรรม
- ความคุ้นเคยโซนเก่าจะค่อย ๆ ลดเมื่อออกไปอยู่โซนอื่นที่ 0.5 วินาทีความคุ้นเคยต่อ 1 วินาทีเกม เพื่อไม่ให้ AI หลบโทษด้วยการข้ามขอบโซนไปมา
- Tiny AI ได้ `ZoneStayPenalty=-min(0.01, elapsedGameSeconds×0.002)` เมื่ออยู่โซนที่เริ่มล้าและไม่เกิดความคืบหน้าจริง การลงโทษนี้ **รวมกับ NoProgressPenalty ใน Experience เดียว** สูงสุด -0.045 ต่อการกระทำ ตัวอย่าง 1 วินาทีเกมไม่มีความคืบหน้าในโซนเก่า = -0.007-0.002 = -0.009 ซึ่งเบากว่าโทษเสีย HP 10 จุด (-0.4) มาก
- อ่านป้ายอย่างเดียว Reward 0 ไม่ลงโทษในการอ่าน, การเดินข้ามโซนอย่างเดียวไม่เพิ่ม Reward และไม่รีเซ็ตความคืบหน้า ส่วนการเก็บของ/สู้/คุย NPC ที่เกิดผลจริงยังมี Reward ตามเดิม
- HUD แสดงหมายเลขโซน เวลาสะสม จำนวนโซนที่เคยไป และ Zone Penalties Accepted; Neural Observation index 28 แสดง Zone Fatigue 0..1 (ค่า 0.5 ที่ 35 วินาที, 1.0 ที่ 70 วินาที) แทน global clock phase เดิม

## การกระจายทรัพยากรแบบเป็นหย่อม (2026-11-02)

NPC ยังกระจายไปหลายพื้นที่ แต่ไอเทมฝึกใหม่ใช้ **กลุ่มแยกชนิด** โดยค่าเริ่มต้นมีเป้าหมายสมุนไพร 2 กลุ่ม หนาม 2 กลุ่ม และหินรูน 2 กลุ่ม สมุนไพรและหินรูนกลุ่มละสูงสุด 12 จุด หนามกลุ่มละสูงสุด 8 จุด ภายในรัศมี 8 หน่วย มีสมุนไพรกระจายเดี่ยวสูงสุด 4 จุด และหนามอันตรายกระจายเดี่ยวสูงสุด 24 จุดทั่ว 4×4 โซนกว้าง ใช้ Seed, การตรวจพื้นแห้งและการเว้นระยะจากวัตถุอื่นเหมือนเดิม ถ้าพื้นที่ไม่เหมาะสม จุดนั้นจะไม่เกิดแทนการฝืนวางลงน้ำ ผู้เล่นและ AI ต้องออกสำรวจเพื่อค้นหาทรัพยากรแต่ละชนิด จำนวนและรัศมีปรับได้ใน `AdventureWorld` Inspector โดยไม่เปลี่ยนกรอบ 4×4 โซนความเบื่อและไม่เปิดเผยพิกัดกลุ่มให้โมเดลทราบ

## NPC และไอเทม
NPC เดิม 3 ตัว (Herbalist Mira, Scout Rowan, Archivist) และสร้าง NPC กระจายใหม่แบบ Seeded ตามพื้นที่ปลอดภัยและแห้งของแผนที่ (ค่าเริ่มต้นทดสอบเพิ่ม 14 คน รวม 17 คน) กด E เพื่อคุยหลังจากหันหน้าตรง จากนั้นเลือก 1=Good หรือ 2=Bad
ไอเทมเดิม 11 จุด และเพิ่มไอเทมฝึกที่กระจายแบบ 8×8 โซนด้วย Seed เดิม โดยแบ่งสมุนไพร หนาม และหินรูน มี Spawn/Respawn เก็บแล้วซ่อน Renderer และ Collider เมื่อครบเวลาจะเกิดใหม่ที่เดิม ใน Seed ค่าเริ่มต้นจุดฝึกใหม่กระจุกเป็นหย่อมแยกชนิด (สมุนไพร หนาม หินรูน) พร้อมสมุนไพรที่พบกระจายบางส่วน จำนวนจริงขึ้นกับพื้นที่แห้งปลอดภัยและ Seed ผ่านการตรวจว่าไม่วางในน้ำและอยู่ตามระดับพื้นดิน

## Adventure Survival Prototype (สัตว์ร้ายและป้ายข้อมูล)

- สัตว์ร้าย Wild Boar 12 ตัวในแผนที่เริ่มต้น เมื่อผู้เล่น/AI เข้าระยะ 9-11 หน่วยจะไล่ตามและโจมตีเมื่อติดระยะประชิด ทำให้ Health ลดลง ตัวที่แข็งแรงมี HP 70 ส่วนตัวปกติมี HP 42 และตาย/เกิดใหม่ตามเวลาเกม 45 วินาที
- การโจมตีสวนกลับใช้คำสั่งเดิม: Manual กด E, Ollama และ Tiny AI ส่ง interact=true; ต้องอยู่ในระยะประชิดและหันหน้าเข้าศัตรู อาวุธและท่าตีแบบเต็มรูปแบบยังไม่มี โดยมีเป้าหมายการทดลองให้ฆ่ามอนสเตอร์ครบ 3 ตัว
- เพิ่มผลไม้ Amberberry สีทอง (+12 Health) และ Duskberry สีม่วง (−32 Health) อย่างละ 6 จุด ทั้งสองแสดงต่อเซนเซอร์เป็น 'Berry' เพื่อไม่ส่งกฎที่ซ่อนไว้ล่วงหน้า
- เพิ่มป้ายข้อมูลในโลก 5 จุด อ่านได้เฉพาะเมื่ออยู่ในระยะและแนวสายตาที่ไม่ถูกบัง เช่น ป้ายเตือน Duskberry มีพิษ และวิธีต่อสู้กับสัตว์ร้าย
- Ollama ได้อ่านข้อความบนป้ายจาก AdventureVision.Report() ภายในระยะที่อ่านได้ เพื่อใช้วิเคราะห์เอง; ทดสอบ qwen3.5:4b แยกจริงแล้วชี้ว่าควรกิน Amberberry และหลีกเลี่ยง Duskberry ได้ถูกต้อง นี่ไม่ใช่การรับรองว่าเล่นเกมเก่ง
- Tiny Transformer ไม่เข้าใจภาษาบนป้าย ป้ายที่ Tiny อ่านจะถูกส่งเข้า /observe เพื่อเก็บข้อความเป็นข้อมูลอย่างเดียว โดย reward=0 และไม่ update weights; ไม่ใช้คำตอบหรือความจำจาก Ollama
- Reward หลังเหตุการณ์: เสีย HP ใช้ตัวคูณ 4.0, ฟื้น HP 2.3 (เมื่อแปลงเป็นสัดส่วน 100 HP), ฆ่ามอนสเตอร์ได้ +1, โจมตีโดน +0.08, Knowledge x0.45, Happiness x0.25 และความเบื่อ x0.02 (ต่ำมาก) โดย Clamp [-2,+2] การเสีย 50 HP จึง -2 มากกว่า Kill 1 ครั้งที่ +1
- เปลี่ยน Numeric Observation ของ Tiny ที่ index 30 ให้เป็น -1 เมื่อเห็นมอนสเตอร์ และให้ทิศทางของมอนสเตอร์ที่มองเห็นมีลำดับสูงก่อนวัตถุอื่น ยังใช้โมเดล 32 มิติเหมือนเดิมแต่มีความหมายของ Feature เปลี่ยน ต้องประเมิน/ฝึกต่อกับเกมใหม่
- แยกชนิดเกมเพลย์กับระบบ Neural Learning: การอ่านป้ายไม่สร้าง Reward, ต่อสู้/เจ็บ/ฆ่าต้องเกิดจริงก่อนจึงค่อยมีผล และการฝึกยังใช้ action_id ครั้งเดียว ระบบ AI ยังไม่เก่งขึ้นโดยอัตโนมัติจนกว่าจะฝึกให้สำเร็จจริง

**ขอบเขตที่ยังไม่มี:** Inventory, ระบบกินอาหารที่เลือกเอง, Hunger/Stamina, อาวุธ, เกราะ, Animation โจมตี, NavMesh/Pathfinding ศัตรูแบบเต็ม, และ PPO แบบหลายขั้น

## Anti-Stall Training: Happiness และความคืบหน้าจริง (2026-11-02)
ตัวละครมี Happiness แทน Relationship เดิม และนับ `MeaningfulProgressCount` จากการเก็บของมีประโยชน์ การเรียนรู้ใหม่ การสนทนากับ NPC และการโจมตีโดน/ฆ่ามอนสเตอร์ การเดินไปมาเพียงอย่างเดียวไม่ใช่ความคืบหน้า หลังไม่มีเหตุการณ์ลักษณะนี้เกิน `progressGraceSeconds=12` วินาทีเกม Happiness จะลด `happinessLossPerMinute=3` หน่วยต่อนาที แม้ Boredom จะยังต่ำ

ใน Tiny Train in Game ตัวเรียนจะได้รับ `PassiveNoProgress` Reward เป็นโทษเล็กน้อย `−min(.035, elapsedGameSeconds×.007)` หากคำสั่งนั้นไม่สร้างความคืบหน้าและพ้นระยะ Grace แล้ว โทษเชื่อมกับ action_id ของคำสั่งที่ใช้จริง ส่งไม่ถี่กว่า 1 ครั้งต่อ 1.5 วินาทีเกม และจะไม่ส่งซ้ำเมื่อมีการใช้ ID ให้รางวัลจากผลจริงไปแล้ว คำสั่งอ่านป้ายมี Reward = 0 ไม่คิดโทษนี้ HP ยังคงมีความสำคัญมากกว่าหลายเท่า

โหมด Train ใช้ stochastic policy sampling เพื่อให้ทดลองคำสั่งใหม่ ส่วน Evaluate เป็นแบบ deterministic โดยไม่มีการอัปเดตน้ำหนัก HUD แสดง Happiness, เวลาไม่คืบหน้า และจำนวนโทษที่ยอมรับแล้ว เอกสารเชิงเทคนิคเพิ่มเติมอยู่ใน AdventureTinyLLM/docs/REAL_GAME_TRAINING_TH.md

## Survival RPG — ต่อสู้ มอนสเตอร์ ผลไม้ และป้ายข้อมูล (2026-11-02)
เพิ่มมอนสเตอร์ Wild Boar 8 ตัวกระจายห่างกันอย่างน้อยประมาณ 9.9 หน่วยใน Seed ทดสอบ โดยมีไล่ผู้เล่นในระยะ ตรวจพบแล้วเดินเข้าหาและโจมตีลด HP มี HP ของศัตรูเอง การถูกฆ่าและการเกิดใหม่ เป้าหมายเริ่มต้นคือฆ่าให้ได้ 3 ตัว กด E (Manual), interact=true (Ollama) หรือ Tiny interact head เพื่อฟันเมื่อหันหน้าและอยู่ใกล้ โดยยังไม่ได้ทำ Animation, อาวุธ, Inventory หรือ Pathfinding เต็มรูปแบบ

เพิ่ม Amberberry สีทอง 6 จุด (+12 HP) และ Duskberry สีม่วง 6 จุด (−32 HP) พร้อมป้ายอ่านได้ 5 จุด รวมไอเทมแผนที่ 107 จุดและ NPC 17 คน **การเดินเข้าใกล้ผลไม้จะไม่เก็บกินอัตโนมัติ** ต้องกด E/interact ในระยะและหันหน้าหาผลไม้ก่อน ระบบอื่นเดิมยังเก็บอัตโนมัติเหมือนเดิม ทำให้ Ollama สามารถอ่านป้ายและหลีกเลี่ยงผลไม้มีพิษได้อย่างมีความหมาย

Vision รายงานผลไม้ทั้งสองแบบว่า Berry พร้อมชื่อ สีที่เห็นได้จริง และทิศ/ตำแหน่ง ไม่ส่งประเภท SafeBerry/PoisonBerry ภายใน; Ollama อ่านข้อความป้ายจากระยะและมุมมองที่เหมาะสม ส่วน Tiny รับข้อความผ่าน /observe แบบ Zero Reward ไม่อัปเดตน้ำหนัก ไม่ใช่การเข้าใจภาษาธรรมชาติ Tiny ใช้ Numeric Observation 32 ค่าคงเดิมโดยให้ v10=.5 หากพบ Berry, v11 เป็นความต่าง Red−Blue จากวัสดุที่มองเห็น, v13=.5 สำหรับ Sign และ v30=−1 เมื่อมีมอนสเตอร์ที่มองเห็นภายใน 12 หน่วย ซึ่งเป็นการขยายความหมายที่ต้องวัดประสิทธิภาพใหม่จาก Checkpoint เก่า

Reward ตามผลจริง: HP ลดมีน้ำหนัก 4.0 /100, HP ฟื้น 2.3 /100, ฆ่ามอนสเตอร์ +1, โจมตีโดน +0.08, Knowledge 0.45 /100, Happiness 0.25 /100, ความเบื่อเพียง 0.02 /100 อ่านป้าย +0 (ไม่ส่ง Training Experience) ระบบยังเป็น Event-based Actor-Critic ไม่ใช่ PPO หรือหลักฐานว่า Neural Model ต่อสู้เก่งแล้ว

ทดสอบ Unity EditMode 11/11 ผ่าน รวมผลไม้ที่ต้องเลือกกิน และ Play Mode ยืนยันว่ากด interact แล้ว Amberberry ฟื้น HP +12, Duskberry ลด HP −32, ไม่กินอัตโนมัติ, โจมตีฆ่ามอนสเตอร์ได้จริง, Terrain 16 Chunks คงอยู่ และ Python ทดสอบ /observe โดยไม่มี Gradient Update ผ่าน

## ป้องกันพื้นดินหายเมื่อ Terrain ถูกปิด/เปิดชั่วคราว
พบสาเหตุที่ทำซ้ำได้: VoxelTerrainView.OnDisable() เคย Shutdown ข้อมูลแสดงผลทั้งหมด แต่กลับเปิดคอมโพเนนต์แล้วไม่มีการ Initialize ซ้ำ ทำให้ Mesh 16 Chunks หายจาก View ทั้งที่ VoxelWorld ยังเก็บข้อมูลพื้นดินอยู่
แก้เป็น preserveOnDisable เฉพาะโลก Adventure เพื่อรักษา Chunk Mesh ระหว่างปิดชั่วคราว ค่าเริ่มต้นของระบบ CityBuilder ที่ใช้ VoxelTerrainView ยังเหมือนเดิม และเพิ่ม AdventureWorld ตรวจสุขภาพ Terrain ทุก 2 วินาทีเวลาจริง หาก View สูญหายจะเริ่ม Initialize หรือ Queue rebuild จากข้อมูล VoxelWorld โดยไม่สร้างเกมใหม่
ตรวจจริง: ปิด/เปิด View แล้ว Mesh ยังคง 16/16 และทดลองสั่ง Shutdown() ระหว่าง Play Mode พบว่าสามารถสร้าง Terrain กลับมา 16/16 ภายในรอบตรวจได้

### แก้ตัวละครตกผ่านพื้นหลัง Unity Domain Reload (2026-11-02)
พบสาเหตุซ้ำได้จาก Unity จริง: แม้ Mesh พื้นแสดงครบ แต่ ModuleRuntime และ IWorldQuery ที่เป็น managed fields หายไปหลัง Unity Recompile/Domain Reload ใน Play Mode เมื่อ AdventureAgent เรียก GroundHeight() เดิมจะได้ 0 และ MovePosition ไปที่ Y=0.87 โดยไม่มีแรงโน้มถ่วง (Rigidbody isKinematic=true, useGravity=false)

แก้ไข: AdventureWorld.HasGroundData และ AdventureAgent.Update/FixedUpdate หยุดเคลื่อนที่เมื่อข้อมูล Voxel World ยังไม่พร้อม GroundHeight คืน NaN แทนค่าปลอม 0; AdventureWorld สร้าง ModuleRuntime/IWorldQuery กลับจาก Seed เมื่อพบว่าหาย เชื่อม Terrain View และผูก NPC/ไอเทมที่มีอยู่ ไม่สร้างซ้ำ จากนั้นย้ายเฉพาะตำแหน่ง Y ที่ต่ำกว่าพื้นกลับขึ้นมา

ทดสอบโดยสั่งทำลาย ModuleRuntime และล้าง query ระหว่าง Tiny Train in Game 8x พบว่าระบบฟื้น 16/16 Terrain Chunks, 95 ไอเทม และ 17 NPC; ตัวละครอยู่ Y=12.87 บนพื้น Y=12; ไม่พบ API request ล้มเหลวในชุดทดสอบนี้ กลับไป Evaluate 1x และ fixedDeltaTime=.02 ได้ตามปกติ การฟื้น Runtime ใช้ Terrain Seed เดิม ไม่ใช่การบันทึก voxel edits ระหว่างการเล่น
