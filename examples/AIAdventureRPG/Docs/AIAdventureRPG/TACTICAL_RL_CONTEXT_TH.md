# ระบบสถานะการต่อสู้และรางวัล Tiny AI

อัปเดต 2 พฤศจิกายน 2026 — ใช้กับโปรเจกต์ `AIAdventureRPG`

## 1. สถานะที่ AI รับรู้

`AdventureCombatState` มีวงตรวจจับรอบตัวละครในแนว X/Z โดยค่าเริ่มต้น **9 หน่วย** เมื่อมอนสเตอร์ที่ยังมีชีวิตเข้ารัศมีจะเข้า `COMBAT` หรือเมื่อมีการโจมตี/ถูกโจมตีก็จะเข้าสู่ COMBAT เช่นกัน เมื่อไม่มีมอนสเตอร์อยู่ในรัศมีแล้วจะกลับ `NORMAL` หลังรอ 1.5 วินาที ไม่จำเป็นต้องฆ่ามอนสเตอร์ก่อนจึงจะหนีออกจาก Combat ได้

`LOW HP` เมื่อ HP **ต่ำกว่า 20%** และ `LOW MP` เมื่อ MP **ต่ำกว่า 20%** เป็นสถานะที่ซ้อนกับ COMBAT หรือ NORMAL ได้ เช่น `COMBAT / LOW HP / LOW MP` โดย AI รับทราบค่าจริงทั้ง HP, MP, ความสุข, ความเบื่อ, ตำแหน่ง, ระยะมอนสเตอร์, ทิศมอนสเตอร์ และการเตรียมโจมตี

เลือกตัวละครใน Unity Scene View จะเห็นเส้นวงสีเหลืองแสดงรัศมีตรวจจับ สามารถแก้ `detectionRadius`, `exitGraceSeconds`, `lowHealthPercent`, `lowMagicPercent` ได้ในคอมโพเนนต์ Combat State

## 2. หลักการให้รางวัล

| เหตุการณ์จริง | คะแนนหลัก |
|---|---:|
| มอนสเตอร์ตายจากการโจมตีปกติ | +1.45 |
| โจมตีปกติโดนมอนสเตอร์ | +0.25 |
| สกิลโจมตีโดนมอนสเตอร์ | +0.30 ต่อเป้าหมาย (จำกัดโบนัส +0.50) |
| สกิลฆ่ามอนสเตอร์ | +1.45 เพิ่มจากคะแนนโดน |
| หลบการโจมตีที่มอนสเตอร์เริ่มฟันแล้วสำเร็จ | +0.35 |
| เห็นหนามแล้วเดินห่างออกไปจริงโดยไม่โดน | +0.28 |
| โจมตีปกติพลาด | −0.20 |
| สกิลใช้ไม่ได้ / MP ไม่พอ / หันไม่ถูก | −0.13 |
| ใช้สกิลโจมตีแต่ไม่โดนเป้าหมาย | −0.22 และต้นทุน MP |
| เสีย HP ในสถานะ HP ปกติ | −0.04 ต่อ HP ที่เสีย |
| เสีย HP เมื่อก่อนโดนเหลือต่ำกว่า 20% | −0.075 ต่อ HP ที่เสีย |
| ตาย | **−2.00** |
| ฟื้น HP ด้วยสมุนไพรขณะก่อนเก็บ HP ต่ำกว่า 20% | โบนัส +0.60 พร้อมคะแนนตาม HP ที่ฟื้นจริง |
| เพิ่ม MP ตอนก่อนเก็บ MP ต่ำกว่า 20% | โบนัส +0.48 พร้อมคะแนนตาม MP ที่เพิ่มจริง |
| เพิ่ม HP/MP ในช่วงปกติ | คะแนนบวกตามค่าที่เพิ่มจริง ต่ำกว่าช่วงวิกฤต |
| เก็บสมุนไพรตอน HP เต็ม | −0.18 ก่อนผลสถานะย่อย |
| เก็บไอเทมเพิ่ม MP ตอน MP เต็ม | −0.12 ก่อนผลสถานะย่อย |
| อ่านป้าย | ไม่ส่งรางวัลให้ Trainer |

คะแนนเป็นองค์ประกอบหลัก อาจบวกผล HP/MP ที่เปลี่ยนจริงอีกเล็กน้อย แล้วจำกัดผลลัพธ์สุดท้ายไว้ที่ −2.0 ถึง +1.95 เปลี่ยนค่าหลักได้ใน `AdventureRewardPolicy.cs` เช่น `Kill`, `NormalHit`, `Dodge`, `CriticalHPPercent`

**ห้ามให้รางวัลจากเพียงคำสั่ง:** การเลือกโจมตี/เลือกหลบไม่ได้คะแนนทันที ต้องยืนยันผลเกิดจริง มอนสเตอร์มีช่วงเตรียมโจมตีประมาณ **0.55 วินาที** พร้อมแสงแดง และให้รางวัลหลบเมื่อออกนอกระยะทันก่อนโดนพร้อมเคลื่อนที่อย่างน้อย 0.6 หน่วย การหลบหนามต้องเห็นหนามก่อน เคลื่อนที่ห่างเพิ่มอย่างน้อย 1.25 หน่วย และไม่มีความเสียหายระหว่างคำสั่งนั้น

คะแนน HP/MP ตรวจ **ค่าก่อนเกิดเหตุการณ์** ผ่าน `pre_hp`, `pre_mp`, `max_mp` พร้อมเกณฑ์ `hp_low_ratio` / `mp_low_ratio` ที่อ่านจาก Combat State จริง เพื่อแยกกรณีวิกฤตอย่างถูกต้อง แม้ผู้เล่นเปลี่ยนเกณฑ์จากค่าเริ่มต้น 20% เป็นค่าอื่นใน Inspector สถานะ HUD, Tiny และสูตรรางวัลจะยังตรงกัน ใช้ผลลัพธ์กับ `action_id` ได้ครั้งเดียว ไม่ส่งรางวัลซ้ำจากเหตุการณ์เดียวกัน

## 3. Tiny API และการฝึกใหม่

โมเดลปัจจุบันใช้ `schema_version=4` กับ **51 features** โปรโตคอล `explicit-action-id-v5-tactical` โดยเพิ่ม 8 ข้อมูลต่อจาก 43 ค่าเดิม:

- 43: COMBAT (0/1)
- 44: LOW HP (0/1)
- 45: LOW MP (0/1)
- 46: ระยะมอนสเตอร์ที่อยู่ในวงตรวจจับ (ปรับสเกล 0–1)
- 47–48: ทิศ X/Z ไปหามอนสเตอร์ที่ตรวจจับได้
- 49: มอนสเตอร์ที่ตรวจจับได้กำลังเตรียมโจมตี (0/1)
- 50: ระยะหนามที่ **มองเห็นจริง** (ไม่มีหนามในระยะ = 1)

ไม่ส่งตำแหน่ง/ทิศมอนสเตอร์ที่อยู่นอกวงตรวจจับผ่านช่อง tactical และไม่ส่งชนิดพิษของผลไม้ที่ยังไม่ทราบ

น้ำหนักเดิม 43 features ถูกสำรองที่ `AdventureTinyLLM/checkpoints/legacy/tiny-unity-pre-tactical-v3-43features-2026-11-02.pt` ไม่ถูกลบหรือเขียนทับ โมเดล 51 features สร้างใหม่จากน้ำหนักสุ่มและฝึกจริงผ่าน `TRAIN TINY` ส่วน `USE TRAINED` เป็น inference ไม่อัปเดตน้ำหนัก

## 4. รีเซ็ตบริบท Ollama

ใน HUD โหมด OLLAMA มีปุ่ม **RESET OLLAMA CONTEXT** เพื่อล้างไฟล์ `brain-memory.txt` และประวัติสนทนาภายในของ Ollama รวมถึงป้องกัน callback เก่ากลับมาสั่งตัวละคร และไม่ส่งประวัติเหตุการณ์ก่อนรีเซ็ตใน prompt ใหม่

การกดปุ่ม **ไม่รีเซ็ตโลกเกม, HP, MP หรือ checkpoint ของ Tiny** ข้อมูลสถานะปัจจุบันและสิ่งที่ตัวละครมองเห็นตอนนี้ยังส่งให้ Ollama ตามปกติ ประวัติใน Stats และ Journal ที่เกิดก่อนรีเซ็ตจะถูกตัดจาก prompt แต่ประสบการณ์ **ใหม่ที่เกิดหลังรีเซ็ต** จะเริ่มแสดงใน prompt และสะสมความจำได้ตามปกติ

## 5. การตรวจสอบ

- Unity EditMode Tests **69/69 ผ่าน**, C# build **0 errors** (มีคำเตือนการ deserialize ที่ไม่ใช่ build error)
- Tiny Python pytest **29/29 ผ่าน**; API `observation_size=51`, `explicit-action-id-v5-tactical`, 66 online training updates
- Unity Play Mode: สถานะในรัศมีและการหนีออก, 51-feature observation, ปรับ Low HP/MP เป็น 30% แล้วคะแนนสอดคล้องจริง, ทดสอบ USE TRAINED จำนวน 23 action ไม่มี API failure และไม่ฝึกเพิ่ม
- ทดสอบรีเซ็ต Ollama บนไฟล์ชั่วคราวแยก: ประวัติเก่าไม่เข้าพรอมป์ตใหม่, เหตุการณ์หลังรีเซ็ตกลับมาปรากฏได้, HP/MP และไฟล์ความจำจริงไม่ถูกแก้ระหว่าง QA
- Unity Console ในการทดสอบ Play Mode รอบนี้ **0 errors / 0 warnings** และออกจาก Play Mode กลับสู่ Edit Mode
