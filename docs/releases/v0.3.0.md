# AdventureTinyLLM v0.3.0 — Reactive AI & Spatial Memory (Unity Example)

**Release date:** 2026-11-03  
**Previous release:** [v0.2.0](https://github.com/funggier/AdventureTinyLLM/releases/tag/v0.2.0) remains untouched.

This release adds a **live, event-driven perception layer** and a **persistent, bounded coordinate memory** to the AIAdventureRPG integration, while keeping the Tiny transformer compact and its reward attribution tied to real outcomes.

## Main features

**Dual concentric detection (9 / 18 world units)**
- The **9-unit inner radius** notifies AI when a *new* recognized hostile, herb, thorn, berry, LoreStone or NPC enters close range. A new alert can interrupt an ongoing measured walk and request a fresh policy decision.
- The **18-unit outer radius** provides hysteresis: the *same entity* cannot trigger repeated alerts simply by moving 8.9 → 9.1 → 8.9 units. It must first move beyond 18 units, then return inside 9.
- Vision remains forward-facing and occlusion-aware for items, while the combat detector senses live monsters **360°** within its 9-unit range, including behind the character.
- Alerts are batched and throttled (default 0.65 game seconds) to avoid issuing an AI request for every herb in a group. **Observation alone yields no training reward.**

**Persistent five-record FIFO map**
- X/Z world coordinates are grouped into **2-unit cells** by default, each retaining the **latest five observations**. Entries contain object kind/name, actual position, UTC timestamp and change type: FirstSeen / Unchanged / Moved / MovedAway / Changed.
- Static herbs are not appended on every scan; unchanged observations are sampled at a slower interval. A moving monster leaves records at both its old and new coordinates.
- Saved as JSON under Unity's `Application.persistentDataPath`, keyed by map seed and dimensions; writes use a temporary file and replacement, with dual game-time / wall-clock throttling at accelerated training speed. The maximum number of remembered cells is configurable (default 2,048).
- At *decision time*, look up the latest five records for the most relevant coordinate: **telegraphed hostile attack > new discovery > currently sensed monster > ordinary visible object**. No hidden monster position is retrieved from the world registry outside the detection ring.

**AI control and protocol**
- **Tiny v5 observation schema: 56 numeric features**, preserving the previous 51 in order and adding five spatial-memory summaries: recent alert, count of coordinate observations, change count, stability, and whether the focused object moved.
- **Protocol:** `explicit-action-id-v6-spatial`. API rejects incompatible 51-feature clients/checkpoints, preventing accidental training with the wrong input projection.
- Tiny's reactive replan cancels stale in-flight action requests and their credit IDs; Ollama cancels stale responses and regenerates a prompt with both *visible* and *proximity-sensed* coordinate history, up to four coordinates, five records each.
- Trained Tiny and Ollama remain distinct modes; **USE TRAINED** does not update model weights. **RESET OLLAMA CONTEXT** continues to clear only Ollama history, not the game or Tiny checkpoint.

**Tuned hit rewards**
- Successful normal melee hit **+0.35** (was +0.25).
- Successful damaging ability **+0.40 per target**, capped at +0.65 hit bonus (was +0.30 and +0.50).
- Verified kill bonus still **+1.45**; death remains **−2.00**. Full rule table and numerical examples: `docs/REWARD_POLICY_TH.md`.
- These are actual-outcome rewards, not points for selecting the attack button.

## Setup

1. Extract the Python source archive and install Python 3.11+ with compatible PyTorch and package dependencies.
2. Run `powershell -ExecutionPolicy Bypass -File .\scripts\start_api.ps1 -EnableOnline` from the extracted source directory. This binds **127.0.0.1:8765** only. Verify `GET /health`: `observation_size=56`, `action_protocol=explicit-action-id-v6-spatial`.
3. Integrate the Unity example into a Unity 6 project **that has the HMGF dependencies**, open `Assets/AIAdventureRPG/Scenes/AdventureValley.unity`, then select **TRAIN TINY**, **USE TRAINED**, **OLLAMA**, or **MANUAL**.
4. Read `examples/AIAdventureRPG/README.md` and `docs/SPATIAL_MEMORY_TH.md` for the full workflow and configuration.

## Known limitations

The tiny model receives **five numerical summaries** of the selected coordinate's five-event history, rather than the complete five text records Ollama can read. This is intentional to preserve a compact input. Its online method is a simple one-step actor-critic, not a proven tactical planner, and model quality has **not** been benchmarked across controlled seeds/episodes. The map tracks objects actually observed/sensed by supported sensors, not all decorative trees or omniscient terrain entities.
