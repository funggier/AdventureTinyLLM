# AdventureTinyLLM v0.3.1 — Urgent Combat Reaction Patch

**Release date: 2026-11-03**

A focused patch on the 56-feature AIAdventureRPG / Tiny API v0.3.0 integration. Previous tags and releases are unchanged.

## Improvements

- **Per-attack reactive awareness:** `AdventurePerceptionMemory.ObserveAttackWindup()` detects a **new committed strike windup** from an already-known monster within the 9-world-unit combat radius. It reports exactly **one urgent event per windup**, keyed by monster entity identity and windup end-time.
- **No need to leave the outer ring:** Repeated attacks from the same monster do not require exiting and re-entering 18 world units to become urgent. The 9/18 rule still applies unchanged to ordinary new object discovery.
- **No discovery cooldown for urgency:** Urgent events bypass the ordinary 0.65-game-second batching window. A queued initial discovery for the same monster is removed to avoid an unnecessary second interruption.
- **Immediate re-evaluation:** The AI stops its current finite walk. Tiny invalidates previous action IDs, aborts an outstanding `/act` request and ignores its stale reply; Ollama cancels the previous response and remembers the urgent threat in the prompt.
- **No counterfeit rewards:** Detecting a threat gives no bonus and no optimizer update. A successful actual dodge must still be confirmed by the world simulation before reward. If a threat appears while Tiny is encoding the observation, the obsolete `/act` request is not sent.
- **HUD:** Tracks the count of urgent windup interrupts separately from ordinary perception alerts.

## Compatibility

- Unity `AIAdventureRPG` example remains a **real module**, not a turnkey standalone Unity project; requires **HMGF.Core / HMGF.World / HMGF.Presentation**.
- **No observation schema migration:** Tiny still uses exactly **56 numeric features** (`schema_version=5`, `action_protocol=explicit-action-id-v6-spatial`). Existing 56-feature trained weights and online checkpoints remain compatible; there is **no reason to reset or retrain** due to this patch.
- The previous trained 51-feature policy is preserved in the user's separate local legacy checkpoint folder and is not distributed.
- Python source and Unity example ship separately; no private model checkpoints, City Builder files or user memory are packaged.

## Behavioral limitation

A monster strike has a default **0.55-game-second** preparation window. Network/model inference may take longer than this interval (especially in accelerated simulation). This patch **requests immediate reconsideration**, but does **not guarantee a dodge** or inject scripted evasion into the learned policy. Measuring actual dodge rates, interrupted request counts, and response latency across episodes remains a separate evaluation task.
