# AdventureTinyLLM — ฝึกผ่านเกมจริง

## ทางเลือกฝึก

**Synthetic Training** รันไฟล์ scripts/train.ps1 ฝึก Transformer จากสถานการณ์จำลอง 2D บน Python/PyTorch แล้วบันทึก checkpoints/tiny-v1.pt

**Train in Game** รัน scripts/start_api.ps1 -EnableOnline แล้วเปิด Unity ฉาก AdventureValley จากนั้นกด TAB จนเป็น Tiny และกด **Train in Game** ใน HUD ตัวละครจะใช้ Neural Policy เดินในเกมจริง และส่งผลจากการเก็บไอเทมหรือปฏิสัมพันธ์ไปฝึกเมื่อเกิดเหตุการณ์จริง

**Evaluate (freeze)** เป็นค่าเริ่มต้น ไม่ส่ง Reward ไปฝึก แม้ API จะอนุญาต Online Training เพื่อไม่ให้ทดลองเล่นแล้วแก้น้ำหนักโดยไม่ตั้งใจ

### Fast Training ในฉากเกมจริง

เมื่อเลือก Train in Game สามารถกด **1x / 2x / 4x / 8x** เพื่อเร่งเวลา Unity และระบบเก็บของ/Respawn/การเคลื่อนที่ โดยระบบปรับ fixedDeltaTime ตามรากที่สองของตัวคูณ เพื่อลดภาระ Physics เมื่อเทียบกับการเพิ่มจำนวน FixedUpdate ตามตัวคูณตรงๆ ขณะยังจำกัดระยะที่ตัวละครเคลื่อนที่ต่อขั้น (ความแม่นยำการชนอาจเปลี่ยนจาก 1x)

เมื่อกด Evaluate (freeze), สลับไป Human/Ollama หรือออกจาก Play Mode จะคืน Time.timeScale=1 และ fixedDeltaTime ปกติ ไม่เปลี่ยนกล้องเดิม

HUD แสดง **Measured sim (x real), actions/s, API latency (ms/request) และ accepted training outcomes/min** เพื่อดูความเร็วที่เกิดขึ้นจริง ไม่ใช่ยึดตัวคูณที่เลือกอย่างเดียว ตัวเลขจากหนึ่งช่วงทดสอบบนเครื่องนี้: 1x = 1.01x / 1.43 requests/s; 4x = 4.05x / 5.67 requests/s; 8x = 8.10x / 11.17 requests/s โดยไม่มีข้อผิดพลาด API ระหว่างวัด แต่ตัวเลขจะเปลี่ยนตาม CPU, GPU, การเรนเดอร์ และ API

**ความเร็วเวลาเกมไม่เท่ากับอัตราเรียนรู้**: ถ้า AI ไม่พบวัตถุที่จะเกิด Reward แม้จะเร่งเวลา 8x ก็อาจไม่มี Neural Weight Update เพิ่ม และไม่มีการรับรองว่าพฤติกรรมดีขึ้นเร็วตามตัวคูณ แนะนำเริ่มที่ 2x หรือ 4x เพื่อรักษาความเสถียร ก่อนทดลอง 8x

start_api.ps1 เลือก checkpoints/tiny-unity-online.pt ก่อน หากมี แล้วจึง fallback ไป checkpoints/tiny-v1.pt; เมื่อเปิด -EnableOnline จะบันทึก Checkpoint จากเหตุการณ์เกมจริงที่ checkpoints/tiny-unity-online.pt เพื่อ Resume ได้

## การกระจายจุดฝึก และความคงทนของ Terrain (AIAdventureRPG)

เกม Unity มีจุดฝึกเดิม 11 จุดและ NPC เดิม 3 คน และล่าสุดเพิ่มการสร้างจุดฝึกแบบกระจายเชิงพื้นที่ (8×8 โซน ควบคุมด้วย Seed) ที่ตรวจระดับพื้นและหลบน้ำ/ภูมิประเทศชัน พร้อมเว้นระยะห่างจากต้นไม้ หินและจุดเกิด เมื่อใช้แผนที่เริ่มต้น 64×64: **ไอเทม 95 จุด (เพิ่ม 84) และ NPC 17 คน (เพิ่ม 14)** ครอบคลุม **63/64 โซน**; ไอเทมมีสมุนไพร หนาม หินรูน และ NPC สอนหัวข้อต่าง ๆ ผ่านการโต้ตอบปกติ

สาเหตุหนึ่งของพื้นดินหายที่ทำซ้ำได้คือ VoxelTerrainView เรียก Shutdown() ใน OnDisable() แต่ไม่มีการสร้าง Mesh คืนเมื่อเปิดอีกครั้ง ปัจจุบัน AdventureWorld เปิดโหมดรักษา Terrain Mesh เมื่อปิดแสดงผลชั่วคราวและตรวจพบกรณีการแสดงผลหลุดแล้วสร้างกลับจากข้อมูล VoxelWorld เดิม โดยไม่แก้ค่าเริ่มต้นของระบบ CityBuilder ที่ใช้ VoxelTerrainView ร่วมกัน

ทดสอบ: ปิด/เปิด Terrain View ยังคง 16/16 Chunk และบังคับเรียก Shutdown() ระหว่าง Play Mode แล้วระบบฟื้นกลับได้ 16/16 Chunk, ไม่ทำให้ข้อมูลพื้นดินสูญหาย ทดสอบ Train in Game 4x พร้อม NPC/ไอเทมจำนวนมากแล้ว API ไม่ล้มเหลว

## Fix: ตัวละครหล่นใต้พื้นทั้งที่ Terrain ยังแสดงอยู่ (2026-11-02)

ตรวจ Unity จริงพบว่าเมื่อ Unity Recompile/Domain Reload ระหว่าง Play Mode โมเดล C# `ModuleRuntime` และ `IWorldQuery` หายไปจาก `AdventureWorld` แต่ Mesh ของ Terrain ยังแสดงอยู่ ทำให้โค้ดเดิม GroundHeight() คืน 0 และ `Rigidbody.MovePosition()` ย้ายตัวละครลงไป Y=0.87 ทั้งที่พื้นที่จริงสูง 12 (ไม่ใช่อาการแรงโน้มถ่วงหรือตัวละครทะลุ MeshCollider)

แก้ใน AIAdventureRPG ที่ `AdventureAgent.cs` และ `AdventureWorld.cs`: หยุดควบคุมตัวละครเมื่อ World Query ยังไม่พร้อม, ใช้ NaN แทน 0 เพื่อไม่ปลอมค่าพื้น, ตรวจจับและสร้าง Runtime/Voxel Query กลับจากแผนที่ Seed เดิม, สร้าง Terrain View ใหม่ และผูก NPC/ไอเทมที่อยู่ใน Scene อยู่แล้ว ไม่สร้าง NPC ซ้ำ และเลื่อนตัวละครกลับขึ้นพื้นเมื่อ Y ต่ำกว่าพื้นจริง

Regression: ทดสอบบังคับให้ World Runtime หายระหว่างฝึก **8x** แล้วตรวจพบว่าฟื้นคืน Terrain 16/16 Chunk, ไอเทม 95, NPC 17, ตัวละคร Y=12.87 บนพื้น Y=12, API requests ไม่ล้มเหลว ทดสอบ Unity Script Reload ซ้ำอีกครั้งพบว่าฟื้นตัวได้เหมือนกัน คืนการเล่นเป็น Tiny Evaluate 1x แล้ว

หมายเหตุ: การคืน World Query ใช้ Terrain Generator จาก Seed เดิม หากอนาคตเกมมีการแก้ไข voxel ที่ต้องคงอยู่ข้าม Domain Reload ต้องเพิ่ม Snapshot/Restore ของโลกแทนการสร้างจาก Seed อย่างเดียว

## Boredom เต็ม 100 และผลต่อเกม (2026-11-02)

ใน AIAdventureRPG ถ้าตัวละครไม่ขยับนานเกิน 7 วินาที Boredom จะเพิ่มขึ้น; เมื่อเต็ม **100/100** ค่า Health, Knowledge และ Relationship จะค่อย ๆ ลดลงตามเวลาเกม โดยค่าเริ่มต้น −3/−2/−2 หน่วยต่อนาทีตามลำดับ และ Development −1 ทุก 30 วินาทีเกม (ตั้งค่าได้ใน AdventureStats Inspector) หากเคลื่อนที่หรือทำกิจกรรมจนความเบื่อลดต่ำกว่า 100 การลดค่าเหล่านี้หยุดทันที และไม่ปล่อยให้ค่าติดลบ

เมื่อตั้ง Fast Training 8x เวลาจำลองเดินเร็วขึ้น ค่าสถานะจึงลดเร็วขึ้นตามเวลาในเกมด้วย และตั้งแต่ระบบ **Anti-Stall Boredom Feedback** ปัจจุบัน เมื่อ Boredom เพิ่มจริงหลังคำสั่งที่ตัวละครแทบไม่เคลื่อนที่ จะส่ง Reward ติดลบเล็กน้อยกลับไปที่ `action_id` ของคำสั่งนั้นด้วย แม้ไม่มีเหตุการณ์เก็บของหรือคุย NPC; ถ้า Boredom เต็ม 100 และยังค้างนิ่งจะส่งโทษเล็กน้อยเช่นกัน

สูตรค่าเริ่มต้น: `−min(0.06, ΔBoredom × 0.005)` ในช่วง Boredom เพิ่ม, เมื่อเต็มค้างอยู่ `−min(0.025, Δเวลาเกม × 0.005)` ต่อคำสั่งที่เลือกจริง จ่ายได้ไม่ถี่กว่า 1 ครั้งใน 1.5 วินาทีเกม ไม่ลงโทษเมื่อเคลื่อนที่ได้จริงหรือเมื่อ API ใช้เวลานานผิดปกติ ตรวจว่าคำสั่งนั้นไม่ได้ใช้ `action_id` ไปกับเหตุการณ์อื่นแล้ว โทษนี้เล็กกว่า HP ลด 10 จุดอย่างมาก (−0.4)

ใน **Train in Game** จะสุ่มการกระทำตาม Categorical distribution ของโมเดลแทนการเลือก Argmax ซ้ำทุกครั้ง เพื่อให้มีโอกาสทดลองทางเลือกใหม่ ขณะที่ **Evaluate (freeze)** ยังคง deterministic และไม่อัปเดต Weights HUD แสดง `Boredom penalties accepted / attempted` และ Last Penalty เพื่อให้วัดได้โดยตรง ไม่ใช่แค่ดูว่าโมเดลเดินหรือไม่

`LastOutcomeDeltas` ยังแยกการเปลี่ยนค่าจากการเก็บของ/คุย NPC ออกจากความเสื่อมที่สะสมระหว่างเหตุการณ์ เพื่อไม่ให้คะแนนเหตุการณ์นั้นปนกับความเสื่อมก่อนหน้า **ยังไม่ใช่ Full PPO / Multi-step RL** และตัวเลข Anti-Stall ไม่ใช่หลักฐานว่าความสามารถเล่นเกมดีขึ้น การทดสอบอัตโนมัติ Unity EditMode ล่าสุด 15/15 ผ่าน; Python 18/18 ผ่าน รวมทั้งส่ง Reward ลบเข้า `move` ด้วย `action_id` และปฏิเสธ Replay การทดสอบ Unity Train 4× จริงยืนยันว่า `IdlePenaltiesAccepted` เพิ่มเป็น 2, `FailedActions=0` ในช่วงที่ตรวจ และระบบคืน Evaluate 1× แล้ว

ทดสอบ Unity EditMode 5/5 รายการผ่าน ครอบคลุมลดค่า, หยุดทันที, ไม่ติดลบ, ความสม่ำเสมอของเวลาจำลอง และความถูกต้องของ Outcome Deltas

## Survival RPG: การเลือกกินผลไม้ การต่อสู้ และข้อมูลป้าย

เกม Unity ปัจจุบันเพิ่ม Wild Boar 8 ตัวที่เดินไล่ โจมตี ลด HP และสามารถถูกฆ่าและเกิดใหม่ มีผลไม้ Amberberry 6 จุด (+12 HP) และ Duskberry 6 จุด (−32 HP) พร้อมป้ายข้อมูล 5 จุด **ผลไม้ต้องกด E/interact เพื่อกิน** เดินผ่านอย่างเดียวไม่มีผล ส่วนไอเทมเดิมยังเก็บอัตโนมัติ จุดฝึกมีไอเทมรวม 107 จุด และ NPC 17 คนใน Seed ทดสอบ

Tiny ได้รับข้อมูลชื่อป้ายและข้อความผ่าน `/observe` โดยตอบกลับ `reward=0` และไม่ปรับ Weights; นี่เป็นการรับข้อความไว้ในหน่วยความจำโปรเซส ไม่ใช่ความสามารถเข้าใจภาษา ส่วน Ollama เห็นข้อความป้ายเมื่ออยู่ในระยะมองเห็นและอ่านได้จริง และได้รับข้อมูลสีของผลไม้จาก Renderer ไม่ใช่ชนิดมีพิษจากกฎเกม

Reward ฝึกจากผลการกระทำจริงให้ HP สำคัญที่สุด (HP ลดมีน้ำหนัก 4.0, HP ฟื้น 2.3), ฆ่ามอนสเตอร์ +1, ตีโดน +0.08, Knowledge .45, Relationship .25 และความเบื่อมีน้ำหนักเพียง .02 เท่านั้น การกินผลไม้จะจับคู่ `credit=interact` เมื่อมี action_id ที่ถูกต้อง โครงสร้าง Input ยังคง 32 ค่าโดยมีข้อมูลภัยใกล้ตัวและสีของผลไม้ให้เรียนรู้ได้ แต่ยังไม่ได้ฝึกภาษา/ความเข้าใจป้ายจากข้อความ

รายละเอียดและข้อจำกัด: [Survival combat & signs](SURVIVAL_COMBAT_SIGN_TH.md)

## Action attribution

- /act คืน action_id เฉพาะแต่ละคำสั่ง
- /experience ต้องมี action_id, credit ประเภท move/interact/answer และ reward ที่มาจากผลจริงหลังเหตุการณ์
- เซิร์ฟเวอร์ปฏิเสธ ID ซ้ำ, ใช้แล้ว, หมดอายุ, agent ผิด, หรือการกระทำที่ Navigation Assistant เปลี่ยนทิศแทนโมเดล
- Unity ตรวจความใกล้ของแหล่งเหตุการณ์ก่อนส่ง เพื่อไม่เผลอฝึกจากเหตุการณ์ทดสอบที่เรียกจากระยะไกล
- เปิด Train in Game จะปิดตัวช่วยเลี้ยวหลบสิ่งกีดขวาง เพื่อให้คะแนนไม่ปะปนกับการควบคุมภายนอก; Evaluate จะเปิดตัวช่วยได้
- ทุกผลที่ได้รับการยอมรับปรับน้ำหนัก Tiny Transformer ด้วย One-step Actor-Critic แล้วบันทึก Neural Weights และ Optimizer

## ข้อจำกัด

เป็นการฝึกผ่านผลลัพธ์ของการเล่นจริงแบบ Event-based ไม่ใช่ PPO หรือ Multi-step RL ที่เสร็จแล้ว ยังมีปัญหา delayed reward, กฎการเคลื่อนที่ kinematic และการสำรวจโดยบังเอิญ ต้องทดสอบแผนที่และ Seed อื่นๆ ต่อไป
Ollama ไม่ใช่ครู และไม่ส่ง Prompt, Memory, ข้อมูลฝึกหรือ Neural Weights ให้ Tiny AI
